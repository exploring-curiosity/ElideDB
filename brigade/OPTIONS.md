# What is left: the reasoning layer for RelMo

Written after the gates failed (`RESEARCH.md` §4a). This is the option space, not
a recommendation dressed as one — each entry says what it costs and what is
actually unknown about it.

---

## The one constraint that organises everything

π0.5 acts only on a **language prefix**. Confirmed in the checkpoint:

```python
def embed_prefix(self, images, img_masks, tokens, masks):
    ...
    lang_emb = self.paligemma_with_expert.embed_language_tokens(tokens)
    embs.append(lang_emb)          # <- the prefix is [images..., language]
```

So a command is either **words**, or **the tensor words would have become**.
Words can come from exactly three places, and two are closed:

| source of words | status |
|---|---|
| generated by a model | **closed** — owner: not generative |
| stored in the database | **closed** — owner: "no other info goes in" |
| a vocabulary | open **only if the vocabulary is discovered, not written** |
| no words at all — inject the tensor | open, and unexplored |

Everything below is a different answer to that one question. Note what is *not*
in question: retrieval. RelMo's query-by-example already works here — a bottle
query returned the wine-rack episodes at 0.67/0.63 above bowl and stove — and
G4 showed the failure was text-noun routing, not retrieval.

---

## A. Latent instruction — no words anywhere

**Mechanism.** A small head maps *(retrieved clip latents, current observation)*
→ the `lang_emb` tensor directly. π0.5 is conditioned without a string ever
existing. Non-generative: it is a regression into a fixed embedding space, not a
decoder.

**Why it is possible.** `embed_prefix` takes the language contribution as a
`(B, T, D)` tensor. Nothing requires it to have come from a tokenizer.

**Training signal.** Each episode in the robot's own history was executed under
some instruction. That instruction is used **once, at training time**, to make
the target tensor — and never stored, never at serve. Same status as any
pretrained weight.

- **Non-generative:** yes.
- **Vocabulary:** none. Nothing is enumerated anywhere.
- **Cost:** small head (~100k–1M params), hours.
- **Unknown, and it is the real risk:** whether π0.5's action expert tolerates a
  prefix that is near but not on the manifold of real token embeddings. Cheaply
  testable before committing — embed a known instruction, pass it through an
  identity-trained head, and see whether the measured success rate survives.
- **Self-supervision:** strongest of any option. The robot's own episodes are
  the training set, so grounding improves as it works. That is precisely the
  "future self supervision" goal.
- **Chat channel:** does not provide one on its own. Pair with E.

This is the standout if it holds. It is also the only option with a real chance
of failing outright for a reason no amount of engineering fixes.

## B. Ranker over a discovered vocabulary — the safe path

**Mechanism.** The reasoning layer is a **ranker**, exactly `vjrel.py`'s shape:
given latents it emits one number, never a word. It scores the request against
candidate *event groups*, and the winning group's own corpus string is the
command. Argmax over a set, not generation.

**Where the vocabulary comes from.** Not from me. Either RoboCasa's 63 released
task strings (26,674 episodes indexed locally by `vjlerobot.py`) or clusters
discovered over RelMo latents. The owner's no-hardwire rule already admits
"corpus vocabulary" as a legitimate replacement for hand-written priors — the
test being that nothing about *this kitchen* is authored by hand.

**Precedent.** `vjrel.py`'s graded relevance already defines "same event" as the
object group (hinged / sliding / basin / vessel / appliance), not the verb —
the owner's own ruling that "a drawer open is not same as cabinet open but a
fridge open is". That taxonomy is the natural label space.

- **Non-generative:** yes — a scorer.
- **Vocabulary:** a released corpus's, never this kitchen's.
- **Cost:** the head already exists and reached **0.894**. Mostly wiring.
- **Unknown:** whether RoboCasa's strings transfer to LIBERO's kitchen well
  enough for π0.5 to execute them. Testable in one afternoon.
- **Self-supervision:** moderate — improves RelMo's metric, not its grounding.
- **Chat channel:** yes, but coarse: it can say which event group, not where an
  object is.

Highest probability of producing a working demo. Weakest novelty: it is MemER
with the generation removed.

## C. Train a kitchen RelMo

**Mechanism.** Fine-tune RelMo's encoder/ranker on kitchen episodes so
query-by-example sharpens in this domain.

- **Honest assessment: this improves the part that is not broken.** G4's failure
  was text routing; QbE retrieval already returns the right episodes. Better
  retrieval does not produce a command, which is the actual blocker.
- **Worth doing for RelMo as a product**, and it feeds the self-supervision
  goal. Worth doing *for this project's blocker*: no.
- Best treated as a follow-on to A or B, not an alternative.

## D. Goal-image actuation — delete language from the loop

**Mechanism.** Retrieved clip's end frame **is** the goal. A goal-conditioned
policy needs no words at all, so the entire constraint above disappears.

- **Cleanest architecture by a distance**, and the strongest product claim:
  video in, video out, nothing textual anywhere.
- **Blocked today:** Octo supports goal images but ships no LIBERO checkpoint
  (published LIBERO numbers are other groups' own fine-tunes), so it fails the
  "already tested and released" bar. Would mean training a policy, not a head —
  a much larger job than A or B.
- Right endgame; wrong thing to start now.

## E. Answer by showing — the chat channel, buildable today

**Mechanism.** "Where is the bowl?" is answered by **retrieving and playing the
span where the bowl last moved**. The reasoning layer ranks; the reply is a
clip and a timestamp, not a sentence. The text channel carries structure —
*which* clip, *when*, *how similar* — and the video carries the meaning.

- **Non-generative:** entirely. No vocabulary at all.
- **Cost:** near zero. Retrieval works, the 3D UI can already play clips.
- **Honest limitation:** it does not produce a π0.5 command, and "the answer is
  a video" is a real product position but not everyone accepts it as an answer.
- Pairs with A or B rather than competing with them.

## F. Ask, when uncertain

**Mechanism.** When the ranker's margin is thin, the robot shows its best
retrieved clip and asks "like this?". The human confirms or corrects, in their
own words, at runtime.

- Needs no vocabulary, stores nothing, and is genuinely agentic — clarification
  is what an agent short of information should do.
- Turns the reasoning layer's *confidence* into a product behaviour instead of
  a hidden threshold.
- Cheap. Pairs with everything.

## The shape of a decision

| | non-gen | vocabulary | blocker solved | risk | self-sup |
|---|---|---|---|---|---|
| **A** latent instruction | yes | none | **yes** | high, but cheap to pre-test | **strong** |
| **B** ranker + corpus strings | yes | released corpus | **yes** | low | moderate |
| **C** kitchen RelMo | yes | none | no | low | strong |
| **D** goal-image policy | yes | none | **yes** | very high cost | moderate |
| **E** answer by showing | yes | none | chat only | none | none |
| **F** ask when unsure | yes | none | partial | none | none |

**A + E + F** is the ambitious build: no vocabulary anywhere, video answers, and
the robot asks when it is unsure. **B + E + F** is the same system with the
command path swapped for something already measured at 0.894 — lower ceiling,
much higher chance of standing up.

The one thing worth doing before choosing between A and B is the half-hour test
that decides A: put a known instruction through `embed_prefix` as a tensor
rather than a string and confirm π0.5's success rate is unchanged. If that
holds, A is live and it is the better project. If it does not, A is dead and B
is the answer, and nothing has been lost.
